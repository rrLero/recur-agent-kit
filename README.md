# recur-agent-kit

HTTP 402 subscriptions for AI agents, settled in USDC on Solana.

An API answers an unpaid request with `402 Payment Required`. An agent pays by opening a capped, cancellable subscription on Solana, retries, and gets the response. Its wallet needs no SOL: Recur pays the network fees. Renewals are pulled on-chain each period by Recur's keeper, never more than the price the agent agreed to.

The wire format is MPP `draft-solana-subscription-00` (the `Payment` HTTP authentication scheme with a `subscription` intent), so the unmodified `pay` CLI can pay these paywalls too.

```
agent                    API + kit-node paywall              Recur                       Solana
  | GET /v1/echo ------------>|                                 |                           |
  |                           |-- POST /agents/challenge ------>|                           |
  |<-- 402 WWW-Authenticate --|                                 |                           |
  | signs subscribe + first pull (0 SOL)                        |                           |
  | GET + Authorization ----->|-- POST /agents/activate ------->| verifies, co-signs, sends |
  |                           |                                 |-------------------------->| subscribe, pull, activate_agent
  |<-- 200 + Payment-Receipt -|<-- receipt ---------------------|                           |
  | later calls: bearer proof, checked against the bound subscription                       |
```

## What's here

| Path | What it is |
| --- | --- |
| `packages/kit-node` | The merchant's side: `recurPaywall(...)` wraps any `fetch`-style handler (Express, Hono, Next.js route handlers, plain `node:http`). Unknown callers get Recur's 402 challenge; a valid credential is relayed to Recur for activation; a paid agent's bearer proof is checked against Recur's binding. Also the Recur API client and webhook verification. |
| `packages/kit-agent` | The agent's side: `recurAgent({ keypair, rpcUrl, budget })` returns a `fetch` that handles the 402 itself, within a monthly budget, from a wallet with 0 SOL. `buildActivation` is the transaction it signs. |
| `packages/solana-client` | The typed client for the `recur` program and the subscriptions rail, generated by Codama from their IDLs. |
| `examples/paywall` | A paywalled echo API (`GET /v1/echo`) on `node:http`. |
| `examples/agent` | An agent that calls it: shows the 402, pays, prints the 200 and the receipt. |

The on-chain program is public at [rrLero/recur-program](https://github.com/rrLero/recur-program), and the devnet deployment is a verified build of it. Recur's API (challenge issuing, activation checks, sponsorship and the keeper) is a hosted service and isn't in this repository.

## Setup

Node 24 and pnpm 12.

```sh
pnpm install
pnpm test        # builds the kits, then runs every test (no network: Recur and the RPC are stubbed)
pnpm typecheck
```

## Run it on devnet

You need a Recur merchant API key and the id of an API product (its `apiBaseUrl` host is the 402's `realm`, so it must match where the paywall runs), and an agent wallet holding Circle devnet USDC (`4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`, from faucet.circle.com) in an existing token account. The wallet needs no SOL.

```sh
RECUR_API_KEY=rk_test_… RECUR_PRODUCT_ID=… RECUR_API_URL=https://… pnpm paywall
AGENT_KEYPAIR=./agent.json pnpm agent
```

## Failed payments

- Every payment failure comes back as a `402` with an RFC 9457 problem (`verification-failed`, `invalid-challenge`, `malformed-credential`) and a fresh challenge, so a client can retry. Recur being unreachable is a `5xx` from the paywall, never a 402: it fails closed.
- A challenge is single use and expires after 5 minutes. A replayed activation or credential is refused.
- When the price is above its budget, `recurAgent` signs nothing and hands back the 402. The on-chain delegation is capped at the plan's price per period.
- An activation that lands but whose follow-up fails is resumed on the agent's next try, or healed by Recur's keeper, without charging again.
- An unpaid renewal answers 402 at once (no grace for agent plans). An agent that cancels its subscription on the rail keeps access to the end of the paid period, and nothing is pulled after that.
